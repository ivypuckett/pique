# Test plan — 9 cards, 2026-08-22

Everything below is implemented and green: **696 unit tests, `deno check`, and
`deno task build` all pass**. What is here is the part a machine cannot sign off
— the desktop webview is native and not drivable from an agent's browser pane,
and the app's HTTP port serves the UI *without* `win.bind` bindings, so a second
browser only ever sees the "Available in the desktop app only" placeholder.

Run it all from the real app:

```bash
deno task dev
```

That command changed (§3). If it does not start, that is itself finding #1.

Mark each ✅/❌ as you go. Anything that fails, say which step and what you saw —
the cards are in **Waiting for human** on the ws-1 board and go back to TODO.

---

## 1. Chat: the message bubble wraps

Card `5b5ef9d0`. Measured fixed, but only against injected markup.

1. In a chat, send a message containing a long unbroken string — a real one is
   best, e.g. paste a 200-character URL or a deep path with no spaces.
2. **The bubble must wrap it.** No horizontal scrollbar under the transcript, no
   text running past the right edge of the chat column.
3. Narrow the chat column with the splitter. It should re-wrap, not clip.

> Known and deliberately untouched: `thinking` and `notice` blocks in the
> transcript did not get the same treatment. If a long token overflows one of
> those, that is a separate card, not a regression.

## 2. Chat: the composer grows

Card `febd2f7a`. The box is a textarea now, not a one-line input.

1. Click into the message box. **It should be exactly one line tall** — if it
   starts four lines tall, the daisyUI floor came back.
2. Type past the end of the line. It grows downward; the transcript above gets
   shorter and stays pinned to the bottom.
3. Keep going past ~10 lines. It stops growing and starts scrolling instead.
4. **Enter sends.** **Shift+Enter inserts a newline** and does not send.
5. Send a multi-line message — the box snaps back to one line.
6. Type `/`, and the command menu opens. Arrow keys move, Enter picks, Escape
   dismisses. Enter must pick the command, **not** send the message.
7. `ctrl+shift+m` from anywhere puts the caret in the box. (This one's selector
   changed — it matched `input[...]` and the element is a `textarea` now.)
8. If you have an IME: start composing, press Enter to accept a candidate. It
   must accept the candidate and **not** send.

## 3. `deno task dev` still works

Card `ca8d5088`. The shell pipeline is now `src/dev.ts`.

1. `deno task dev` builds and launches the app, same as before.
2. The window renders. (If you get "Could not create GBM EGL display", the
   DMA-BUF workaround did not survive the port — that is a fail.)
3. `Ctrl+C` in the terminal ends it.
4. Vite build output and the app's own logs still stream to the terminal.

> Only the Linux branch is exercised here. macOS and Windows are handled and
> unit-tested but **unverified on real hardware** — including whether
> `deno desktop` emits `pique/pique` or a `.app` bundle there. If you have
> either machine, running this on it is worth more than the rest of this plan.

## 4. File tree: case-only rename

Card `5c62e8c4`. On Linux this always worked, so **this step only proves
anything on macOS or Windows.**

1. In the file tree, rename `Foo.ts` → `foo.ts`.
2. It should succeed. Before this change it failed with "already exists".
3. Then check the guard is intact: with both `a.txt` and `b.txt` present,
   rename `a.txt` → `b.txt`. It must still be **refused**, and `b.txt`
   untouched.

## 5. Terminal: shell and editor

Card `60a91cb1`. Also mostly a non-Linux check.

1. Open a terminal tab. Your usual shell, interactive, in the right directory.
2. Open a file with the `$EDITOR` path (however the editor pane invokes it).
3. On Windows, with no `$SHELL` set, you should get `cmd` from `ComSpec` —
   **not** a failure to spawn `bash -i`.

## 6. Kanban: card history — the main new feature

Card `1e8f6b95`. This is the one to spend time on.

1. Open Kanban, click a card. At the bottom of the drawer: **History**, with a
   **Show** button. Collapsed by default.
2. Click Show on a card that has moved columns before — any of the ones this
   session touched will do.
3. Check each entry has: what changed, **who** (`human` / `agent`), **when**,
   and for a move, **the reason**. Newest at the top.
4. Drag the card to another column, give a reason, confirm. **The history
   updates without you pressing anything** — no refresh, no reopening the card.
5. Edit the title, then the description, then tick a subtask. Each should appear
   as its own entry, naming only the field you touched. Long text is cut to ~60
   characters with an ellipsis; a checklist reads as `3 items, 1 done`.
6. Add a predecessor. It should read as the other card's **title**, not a UUID.
7. Rename a column, then look at an old move through it — it should read under
   the **new** name. Delete a column and check an old move through it says
   `(deleted column)` rather than going blank.
8. On a brand-new card: "Nothing recorded yet."
9. In a workspace, flip the board to **Root** while a history is open. It must
   not paint one board's history under the other board's card.

## 7. Subagents: the limits

Card `139ab48a`. 10 minutes and 40 turns, both returning partial text.

1. Ordinary delegation still works: ask chat to `run_subagent` something small
   and confirm it answers normally, with no truncation notice.
2. The limits are hard to hit deliberately without waiting — if you want to try,
   define a subagent whose prompt tells it to keep calling `ls` and never
   answer, then delegate to it. After 40 turns you should get its text back
   **plus** `[subagent <name> was stopped early: it hit its 40-turn limit …]`,
   as a **successful** tool call — not a red failed one.
3. Confirm progress lines still stream under the open `run_subagent` call.

## 8. Subagents: the Library rows

Card `b204f984` — the pre-existing hands-on card, unchanged. In the Library
module:

1. **New subagent**, fill in name / tools / model / description / system prompt,
   Save. A file appears at `~/.pique/scopes/<scope>/agent/agents/<name>.md` with
   that frontmatter.
2. Ask chat to `run_subagent` against it **in the same conversation, with no
   `/reload`**. It must resolve — definitions are re-read per call.
3. Edit it, change the system prompt, Save. The file is rewritten and the **name
   field stayed locked**.
4. `define_subagent` one from chat, then press **Refresh**. It shows up as a row
   the Library can edit.
5. Delete one. The file is gone and `run_subagent` now fails by name.
6. In a workspace, flip **Scope** to **Root**. Edits there land in root's agents
   dir, not the workspace's — and the workspace's own rows come back when you
   flip back.
